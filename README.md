# 🤖 AI Assistant for Electric Motor Controller Documentation (RAG)

AI-ассистент для технической поддержки контроллера управления электродвигателями на базе технологии **Retrieval Augmented Generation (RAG)**.

Система предназначена для поиска информации во внутренней инженерной документации по подключению, настройке и эксплуатации контроллера и генерации ответов с помощью LLM.

---

## 🎯 Цель проекта

Автоматизировать поиск информации в технической документации и создать AI-помощника, который позволяет быстро получать ответы на инженерные вопросы без ручного просмотра больших инструкций.

Примеры запросов:

- Как подключить аналоговую ручку газа?
- Как включить контроллер?
- Какие ограничения по напряжению питания?
- Как настроить профиль мощности?
- Что делать, если контроллер не запускается?

# 🏗 Архитектура системы

Проект реализует полный RAG pipeline:

```
Technical Documentation (DOCX)
              |
              ↓
      Document Processing
              |
              ↓
          Chunking
              |
              ↓

              |
```

# ⚙️ Как работает система

## 1. Обработка документов

Исходные данные:

- Техническая документация контроллера управления электродвигателями;
- инструкции по подключению;
- описание настроек;
- эксплуатационные рекомендации.

Реализовано:

- извлечение текста из DOCX;
- очистка документа;
- структурирование информации;
- подготовка данных для поиска.

---

## 2. Chunking

Документ разбивается на смысловые фрагменты.

Каждый фрагмент сохраняет метаданные:

```json
{
  "source": "technical_documentation.docx",
  "device": "electric_motor_controller",
  "section": "Подключение контроллера",
  "topic": "Аналоговые ручки"
}
```

Это позволяет сохранять связь между найденным текстом и исходным документом.

---

## 3. Создание embeddings

Для преобразования текста в векторное представление используется модель:

```
multilingual-e5-base
```

Каждый текстовый фрагмент преобразуется в embedding размерностью:

```
768
```

Векторное представление позволяет выполнять поиск информации по смыслу, а не только по совпадению ключевых слов.

---

## 4. Векторный поиск

Для хранения и поиска embeddings используется:

```
Qdrant
```

При запросе пользователя:

```
Как подключить ручку газа?
```

система:

1. Создает embedding запроса;
2. Ищет наиболее похожие векторы;
3. Извлекает релевантные части документа;
4. Передает найденный контекст в LLM.

---

## 5. Генерация ответа

Для формирования ответа используется:

```
GigaChat API
```

LLM получает:

- вопрос пользователя;
- найденные фрагменты документа;
- инструкции использовать только предоставленный контекст.

После этого формируется ответ на основе технической документации.
