# Обработанные данные (Processed Data)

Данная папка содержит промежуточные и подготовленные данные, полученные в процессе обработки технической документации для RAG-системы.

Файлы в этой директории являются результатами этапов подготовки данных и используются для создания embeddings, загрузки в векторную базу данных Qdrant и генерации ответов с помощью LLM.

## Описание файлов

### ElectricMotorController-RAG_text.txt

Полный текст, извлечённый из исходной технической документации.

Используется как первый этап обработки документа после парсинга DOCX-файла.

Содержит информацию о:
- подключении контроллера;
- настройках параметров;
- эксплуатационных особенностях;
- технических рекомендациях.


### ElectricMotorController-RAG_sections.json

Документ, разделённый на основные структурные разделы.

Используется для сохранения исходной структуры документа и дальнейшего формирования базы знаний.


### ElectricMotorController-RAG_subsections.json

Документ, разделённый на логические подразделы.

Каждый подраздел представляет отдельную смысловую часть документа:

- подключение;
- настройка;
- параметры;
- диагностика.


### ElectricMotorController-RAG_subsections_clean.json

Очищенные подразделы после предварительной обработки текста.

Выполнено:
- удаление лишнего форматирования;
- нормализация текста;
- подготовка структуры данных для дальнейшего разбиения.


### ElectricMotorController-RAG_chunks.json

Документ, разбитый на небольшие смысловые фрагменты (chunks).

Чанки используются для последующего семантического поиска.

Каждый chunk содержит:
- текстовый фрагмент;
- метаданные;
- информацию о расположении в документе.


Пример:

{
  "text": "Подключение аналоговой ручки газа...",
  "metadata": {
    "section": "Подключение",
    "topic": "Ручки управления"
  }
}


### ElectricMotorController-RAG_chunks_context.json

Чанки с дополнительным контекстом.

В каждый фрагмент добавляется информация о структуре документа:

- раздел;
- подраздел;
- тема;
- источник.

Дополнительный контекст позволяет повысить качество semantic search и улучшить результаты поиска.


### ElectricMotorController-RAG_embeddings.json

Векторные представления текстовых фрагментов.

Для преобразования текста в числовое представление используется модель:

intfloat/multilingual-e5-base

Каждый текстовый фрагмент преобразуется в embedding размерностью 768.

Полученные векторы используются для поиска информации по смысловой близости.


Пример структуры:

{
  "text": "Как подключить ручку газа",
  "embedding": [
    0.001,
    0.043,
    -0.021
  ],
  "metadata": {
    "section": "Подключение"
  }
}


## Использование в RAG Pipeline

Обработанные данные используются следующими этапами:

1. Создание embeddings для текстовых фрагментов.
2. Загрузка векторных представлений в Qdrant.
3. Выполнение semantic search по запросу пользователя.
4. Получение релевантного контекста из документации.
5. Передача найденной информации в LLM.
6. Генерация ответа на основе технической документации.

## Примечание
